# MCP server

`https://api.parroquia.app/mcp` exposes the config API to AI clients (Streamable HTTP, stateless).
Add it as a remote MCP server/connector in any MCP client and log in with your editor email.

## Auth
OAuth 2.1 (authorization code + PKCE, dynamic client registration) on top of the existing credential store:
1. The client opens `/oauth/authorize`; you type your email.
2. A magic link is emailed (same grants as the editor: `auth.enc` is the source of truth).
3. The link opens a consent page (`/oauth/confirm`); approving redirects back to the client with a one-time code.
4. `/oauth/token` swaps code + PKCE verifier for a normal editor token (`via: "mcp"`), valid for every slug the email can edit. Removing the email's grant revokes it immediately.

Discovery: `/.well-known/oauth-protected-resource`, `/.well-known/oauth-authorization-server`.

## Tools
`list_sites`, `get_schema`, `get_config`, `validate_config`, `patch_config`.
Ops use the same vocabulary as `PATCH /sites/:slug/config.json` (see `src/patch.js`).

## Schema and validation
The JSON Schema is generated by the editor repo from `_pages.yml` and published at
`https://editor.parroquia.app/config.schema.json` (override with the `SCHEMA_URL` var). The Worker caches it
for 5 minutes. `patch_config` applies ops in memory, validates the result and saves only if the ops introduce
no NEW schema errors (errors already present in legacy configs do not block unrelated edits). Missing list-item
`id`s are filled server-side. Only sections defined in the schema are editable (e.g. `dev` is not).
Writes are forwarded to the existing PATCH handler, so auto-build and YouTube sync behave as for the editor.

### Field guidance (`help`)
A field in `_pages.yml` can carry a long-form `help` text. The editor shows it as an (i) tooltip for humans, and
the schema generator appends it to that field's JSON Schema `description`, so the AI reads the same text via
`get_schema`. `get_schema` outlines big nodes: each outlined property/variant shows the first 200 characters of its
description (marked `[truncated]` when cut); drill into the field with `path` for the full text. Keep the
important part of a `help` text at the start.
